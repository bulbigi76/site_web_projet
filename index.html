Top Chrono !

1 objectif : 10 secondes

Projet Arduino + Impression 3D

Cahier des charges

Ce projet consiste à concevoir un jeu basé sur un système Arduino permettant de mesurer la précision du joueur sur une durée donnée.

L’objectif est de concevoir un dispositif simple et interactif dans lequel le joueur doit arrêter un chronomètre à un temps précis, ici 10 secondes, à l’aide d’un bouton et d'un écran LCD.

Objectifs du projet

  • Créer un chronomètre interactif avec Arduino ;
  • Afficher le temps sur un écran LCD ;
  • Utiliser un seul bouton pour contrôler le jeu ;
  • Concevoir un boîtier grâce à l’impression 3D.

Le but du joueur est d’arrêter le chronomètre le plus proche possible de 10 secondes.

Fonctionnement du jeu

  1. Le joueur appuie une première fois → le chronomètre démarre
  2. Le temps défile sur l'écran
  3. Deuxième appui → le chronomètre s’arrête et le temps est affiché
  4. Troisième appui → remise à zéro du système

Le code Arduino

Explication du programme

Au démarrage, l’écran affiche un message invitant le joueur à commencer une partie. Tant qu’aucun appui n’est détecté, l’affichage alterne toutes les trois secondes entre ce message et un chronomètre à zéro afin de rendre l’interface plus dynamique.

Le fonctionnement du jeu repose sur trois actions successives du bouton :

  • Premier appui : le chronomètre démarre. Le programme enregistre alors l’instant de départ grâce à la fonction millis(), qui renvoie le temps écoulé depuis la mise sous tension de la carte Arduino.
  • Deuxième appui : le chronomètre s’arrête. Le temps écoulé est calculé puis affiché sur l’écran LCD. Le programme vérifie ensuite si le joueur a réussi à s’arrêter exactement à 10 secondes. Dans ce cas, le message « VICTOIRE ! » apparaît ; sinon, le message « PERDU ! » est affiché.
  • Troisième appui : le système est réinitialisé et revient à l’écran d’accueil, prêt pour une nouvelle partie.

Pendant que le chronomètre fonctionne, le temps écoulé est mis à jour en permanence sur l’écran LCD. Cette mise à jour est réalisée dans la boucle principale du programme, ce qui permet un affichage fluide et en temps réel.

Afin d'éviter les erreurs liées aux rebonds mécaniques du bouton poussoir, un court délai de 200 millisecondes est appliqué après chaque appui détecté. Cette technique permet d'éviter qu'un seul appui soit interprété plusieurs fois par le microcontrôleur.

Code complet


#include <LiquidCrystal_I2C.h>

const int bouton = 1;

LiquidCrystal_I2C ecran(0x27, 20, 4);

unsigned long tempsDepart = 0;
unsigned long tempsEcoule = 0;

bool chronoEnCours = false;
bool etatBoutonPrecedent = HIGH;
bool jeuDemarre = false;

// Pour l'alternance d'affichage
unsigned long dernierChangement = 0;
bool afficherTemps = false;

void setup() {
  ecran.init();
  ecran.backlight();
  pinMode(bouton, INPUT_PULLUP);

  // Message initial
  ecran.setCursor(0, 0);
  ecran.print("Appuie pour");
  ecran.setCursor(0, 1);
  ecran.print("jouer");
}

void loop() {
  bool etatBouton = digitalRead(bouton);

  // alternance visuel 
  if (!jeuDemarre) {
    if (millis() - dernierChangement > 3000) {
      afficherTemps = !afficherTemps;
      dernierChangement = millis();

      ecran.clear();

      if (afficherTemps) {
        ecran.setCursor(0, 0);
        ecran.print("Temps: 0:00");
      } else {
        ecran.setCursor(0, 0);
        ecran.print("Appuie pour");
        ecran.setCursor(0, 1);
        ecran.print("jouer");
      }
    }
  }

  // detection appui
  if (etatBoutonPrecedent == HIGH && etatBouton == LOW) {

    // 1e clic = démarrage
    if (!jeuDemarre) {
      jeuDemarre = true;
      chronoEnCours = true;
      tempsDepart = millis();
      ecran.clear();
    }

    // 2e clic = arrêt
    else if (chronoEnCours) {
      tempsEcoule = millis() - tempsDepart;
      chronoEnCours = false;

      ecran.clear();
      ecran.setCursor(0, 0);
      ecran.print("Temps: ");
      ecran.print(tempsEcoule / 1000.0);

      ecran.setCursor(0, 1);

      if ((tempsEcoule / 10) == 1000) {
        ecran.print("VICTOIRE !");
      } else {
        ecran.print("PERDU !");
      }
    }

    // 3e clic = reset
    else {
      jeuDemarre = false;
      ecran.clear();
    }

    delay(200);
  }

  etatBoutonPrecedent = etatBouton;

  // affichage du chrono
  if (chronoEnCours) {
    tempsEcoule = millis() - tempsDepart;

    ecran.setCursor(0, 0);
    ecran.print("Temps: ");
    ecran.print(tempsEcoule / 1000.0);
  }
}

Impression 3D

Afin de compléter ce projet et de le rendre plus esthétique et plus pratique à utiliser, j'ai réalisé un boîtier en impression 3D.

Conception du boîtier

Le boîtier a été modélisé à l’aide du logiciel Fusion360. Plusieurs contraintes devaient être prises en compte :

  • laisser un emplacement adapté à l’écran LCD ;
  • prévoir une ouverture pour le bouton poussoir ;
  • permettre le passage des câbles ;
  • avoir une taille suffisante pour accueillir la carte Arduino.

Voici quelques captures d'écran de la modélisation 3D sur le logiciel :

Les cylindres visibles permettent de visser les éléments à la structure afin de s'assurer que rien ne bouge.
Le bloc du bas accueille la carte Arduino.
J’ai également soudé le bouton poussoir afin de gagner en place et de rendre plus pratique son installation.

Impression du modèle

Une fois la modélisation terminée, le fichier 3D a été exporté puis préparé pour l’impression. L’impression a été réalisée en plastique PLA.

Résultat final

Chaque pièce s'emboîte et a été collée à la colle forte afin d'assurer le maintien de la structure.

Grâce à l’impression 3D, le projet possède désormais une structure plus propre et plus solide. Le boîtier permet de mieux présenter le jeu et facilite son utilisation. Cette partie du projet m’a permis de découvrir les bases de la modélisation et de mieux comprendre le fonctionnement de l’impression 3D.

Axe d'amélioration du projet

Plusieurs choses peuvent être ajoutées ou modifiées dans le projet.
Tout d'abord,du côté du gameplay, pour rendre le jeu plus fun et plus compétitif, on pourrait faire jouer un deuxième joueur juste après le premier et le joueur le plus proche du temps demandé gagne. Ensuite, il serait possible d’augmenter la difficulté du jeu. Plutôt que de viser uniquement 10 secondes, le système pourrait générer des valeurs aléatoires, comme 8,3 secondes ou 6,7 secondes. Cela rendrait le jeu plus imprévisible et demanderait davantage de précision de la part du joueur.
